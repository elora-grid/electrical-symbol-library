# Contributing

Submit corrections, proposed references or drafting distinctions through a GitHub issue or pull request. Include the entry slug, a precise explanation and an accessible primary source URL from a standards body or manufacturer. Identify the publication revision and the scope of the proposed change where possible.

Contribute only independently authored text and illustrations that you have the right to contribute. Do not submit confidential drawings, project IDs, customer layouts, product dimensions inferred from private documents, copied standards glyphs or unlicensed manufacturer assets. Keep publisher assets linked at their original source.

Use the `symbolVariant` field only when the particular form and convention are supported by cited evidence. Do not label a generic concept preview as a certified IEC/ANSI equivalent. Source context and graphical convention are separate fields.

Run `npm ci`, `npm run build` and `npm run check`. Provide evidence for technical changes; passing a schema check does not establish engineering correctness. Proposed editorial changes must also enter the public Elora catalogue so future snapshots preserve them. Contributions follow the licensing scope in `ATTRIBUTION.md`.
